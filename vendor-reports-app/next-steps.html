Reports can't go out from a Gmail address without landing in spam. You need a real domain with SPF and DKIM records. DNS changes take 24–48 hours to take effect, so this is the item most likely to hold up launch day.

  2. 02

    You5 minutes

    In monday: click your avatar (bottom left) → Developers → My Access Tokens → Show → copy it.

  3. 03

    Install Node.js

    You10 minutes

    Node is the program that runs this app — like needing Excel installed before you can open a spreadsheet. Go to nodejs.org and download the big green LTS button. Accept every default.

    Then open Terminal (Mac: Cmd+Space, type "terminal") or PowerShell (Windows: Start menu, type "powershell") and type this, then Enter:

    node --version
    Done whenIt prints something like v22.14.0. Any number 20 or higher is fine. If it says "command not found", restart your computer and try again — that fixes it nine times out of ten.
  4. 04

    Get the code onto your computer

    You15 minutes

    Install GitHub Desktop from desktop.github.com — it's the click-based way to do this, and you don't need to learn git commands today.

    Sign in, then File → Clone repository → pick xander-formulax/fight-night-pickem. Once it's downloaded, use the Current Branch dropdown at the top and switch to claude/vendor-reports-app-design-xs0s9w.

    The app lives in the vendor-reports-app folder inside it. (Yes, it's sitting in your pick'em repo — that's the shared-repo thing we talked about. It works fine for now.)

    Done whenYou can open that folder and see README.md, package.json, and a src folder.
  5. 05

    Run it — and see your real reports

    You5 minutes

    In Terminal, type cd (with a space), then drag the vendor-reports-app folder onto the Terminal window — it fills in the path for you. Press Enter. Then:

    npm install

    That downloads the pieces the app needs. It only has to be done once. Then paste your token from step 2 in place of YOUR_TOKEN:

    MONDAY_API_TOKEN=YOUR_TOKEN npm run dry-run -- --write

    This cannot send email. There is no email code in that script at all — it reads your boards, builds the reports, and writes them to files.

    Done whenYou get a table of your vendors in the Terminal, plus a new out folder full of .html files. Double-click any of them to see exactly what that vendor would receive.

Phase 2 · The next few weeks

Make the data good enough to send

None of this is programming, and it's the part that decides whether the reports are worth receiving. The dry run from step 5 prints this list for you, so you can watch it shrink.

  • Fill in "Bill to" on every active job. The big one. A vendor whose report is missing half their homes will trust it less than no report at all.
  • Merge the duplicate vendor records. Solitaire currently exists as four separate vendors, Palm Harbor as three, Titan as several. Each duplicate splits one dealership's homes across two reports.
  • Collect report recipient emails. Not the billing email — that's usually accounts-payable. You want whoever actually calls asking for status.
  • Delete the duplicate *Site Checks column on Jobs. There are two with the same name. I can do this one for you.
  • Get crews setting Schedule on tasks. Right now most work has no date, so "Still to do" mostly reads "Not yet scheduled" — which is the weakest version of the report.

Phase 3 · Launch

Put it on monday's servers

This is the only genuinely technical stretch, and we do it together — mostly me running commands and you clicking approve.

  • Pick an email provider and verify the domain. Postmark or Resend. This is where the DNS work from the top pays off.
  • Create the app in monday's Developer Center and deploy the code with mapps code:push.
  • Register the Friday schedule. One command. Test it by hand first with mapps scheduler:run.
  • Pilot with two vendors for two weeks. Pick the two most likely to tell you honestly if something reads wrong.
  • Turn on everyone else. Flip Weekly Report to "On" a few vendors at a time.

Reference

Words I keep using

Terminal / PowerShell
A window where you type commands instead of clicking. Everything you type there is undoable unless it starts with rm or del — so don't run those.
Node.js
The engine that runs JavaScript programs on a computer instead of in a web browser. Our app is a JavaScript program.
npm
Comes with Node. It downloads the ready-made pieces our app depends on. npm install fetches them; npm run something runs one of our commands.
API token
A long password that lets a program log into monday as you. Anyone holding it can read everything you can read.
Repo / branch
A repo is a project folder with full history. A branch is a parallel version of it — ours is claude/vendor-reports-app-design-xs0s9w, so this work stays separate from your pick'em app.
Dry run
Doing everything except the irreversible part. Our dry run builds every report but has no ability to send one.
monday-code
monday's own hosting. You give them your code, they run it on their servers, and it can wake up on a schedule without anyone's computer being on.
Cron
A schedule written in a compact format. 0 20 * * 5 means "at 20:00, every Friday". It runs on UTC time, which is why it drifts an hour when daylight saving changes.
SPF / DKIM
Two settings you add to a domain's DNS that prove your emails are really from you. Without them, mail providers assume you're spam.
Secret
A password stored on the server rather than written in the code — so it never ends up on GitHub. Your monday token and email API key both live here.
