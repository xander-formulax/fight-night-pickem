Vendor Reports

A weekly progress email to every dealership, built from the work already tracked in monday — so they stop calling to ask how it's going.

Build it as a monday Vibe app, object variant — the same shape as the four apps already running in this workspace. It reads Vendors, Jobs and Tasks live, computes each vendor's week, renders an HTML email, and sends after someone clicks Send.

It adds no new boards and three columns to one existing board. The report is a computed view, never stored data. The build is the easy part — the real work is that 80 of 141 jobs currently have no vendor attached, and would appear in nobody's report.

Voice rules

No crew names, no subcontractor names, no prices, no task IDs. Dates read as "Tue, Aug 18." A phase with no movement says nothing rather than "no update" — silence beats filler. And a home with a genuinely quiet week gets the third treatment above: say so plainly, then give the next date. That sentence is the reassurance the vendor was going to call for.

The idea that makes it work

Sixteen columns become one honest number

Every Job carries up to 16 optional phases — Pad, Delivery, Tie Downs, Skirting, Septic, Trim Out and the rest. Each has a …? column saying whether it applies to this home, and a relation pointing at the Task that does the work.

Scope × task status = "7 of 11 steps." That single figure is the most valuable thing the app computes, and nothing in monday shows it today. It is also what makes a progress bar honest: a home that needs no septic isn't penalised for not having it.

One correction first — the Jobs board has two *Site Checks relation columns. Delete one, or Site Check double-counts in every report.

A vendor receiving a report that omits half their homes is worse than receiving nothing — it reads as "you lost my house." So the app ships with a Readiness tab that surfaces these as a live worklist: 12 jobs missing a vendor, 3 vendors missing an email. Cheap to build, and it turns cleanup into a weekly habit instead of a one-time project that decays by month two.

Constraints

Three platform limits worth knowing before you start

  • Vibe apps can't run background jobs. They only run while someone is looking at them — so the weekly send is human-triggered. That's a fine outcome: a proactive customer email deserves a glance before it goes, especially while the data gaps above are open.
  • Files sent from a monday File column arrive as a link, not an attachment — and non-account-members can't open it. So no PDF. The report is HTML in the email body, which is better anyway: the vendor reads it on their phone without opening anything.
  • Vibe can send formatted HTML email through a connected Gmail or Outlook account. That's the delivery path. Worth confirming on day one of the build, since everything else depends on it.

Unattended, fully-automatic sending is the one thing that needs a different architecture — a scheduler, which means leaving Vibe for a hosted app. Revisit after a month of the human-approved loop, not before.

Operations

Ten minutes every Friday

  1. A recurring monday automation pings the office coordinator Friday morning.
  2. They open Vendor Reports. It lists every vendor set to Weekly Report: On, each with a readiness dot — green for ready, amber for missing email or unassigned jobs.
  3. Click a vendor, read the generated report, optionally type a note at the top, hit Send.
  4. Send all ready clears the happy path in one click.
  5. On send: the email goes out, the exact HTML is posted as an Update on the Vendor item, and Last Report Sent is stamped.

What changes in monday

Three columns on the Vendors board — Report Recipients (semicolon-separated text, which monday's Gmail integration fans out to each address), Weekly Report (On / Paused), and Last Report Sent (date). Nothing else. Sent history lives in the Vendor item's Update feed, which answers "what did we tell them last week?" when a vendor calls back.

Scope

Deliberately not in v1

No PDF generation. No vendor login or portal. No photo galleries. No per-vendor branding. No editing schedules from inside the report. No vendor replies routed back into monday. No unattended sending.

Each of these is a reasonable month-three conversation. None of them is what makes a vendor stop calling — a reliable email that arrives every Friday is.

Four calls to make

Open decisions

  • Send day. Friday afternoon reads as "here's your week, here's what's next." Monday morning reads as a plan. Friday fits the reassurance goal better — recommend Friday.
  • Which contact. The billing email is usually accounts-payable, not the person chasing status. That's why Report Recipients is separate — but someone has to go collect those addresses.
  • Include recently finished homes? Recommend yes, for 14 days after completion, marked Complete. Otherwise a finished home silently vanishes from the report instead of visibly landing.
  • The word "vendor." If these go to dealerships, the email body should just use the dealership's own name and never the category noun at all — which sidesteps the vendor-versus-customer question entirely.
